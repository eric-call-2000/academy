### 1. Unit 1 — Many files, one program
Why one file stops scaling; the module pattern by hand, then the syntax: named exports, default exports, module scope, the module cache, circular imports. This is the LANGUAGE half of the course.

Lessons:
  - The module pattern, before there was a keyword
  - export and import (named)
  - Default exports, and why named usually wins
  - Module scope: the accidental global
  - Modules run once — the cache and circular imports
  - Unit 1 quiz: Modules

Graded how:
L1 (kind js, WORKS TODAY, zero engine): learner types `createCounter()` returning `{inc, value}` over a private `count`, then a `registry` object of factories and a `myRequire(name)` that memoizes. Test calls both: `T.expect(myRequire('counter') === myRequire('counter'), 'the cache must return the SAME object')`, `T.eq(myRequire('counter').value(), 0)`, and `T.expect(typeof count === 'undefined', 'count must stay private')`. L2-L5 need moduleHost. L2: two editor tabs, `math.js` and `main.js`; learner types `export function add(a,b){return a+b}` and `import { add } from "./math.js"`. Test asserts the LINK not just the output: `T.eq(T.mod('./math.js').add(2,5), 7)` plus `T.expect(T.logged('7'))` plus a negative — delete the `./` and the test asserts the error text is `Cannot find module 'math.js'`, grading the failure a learner will actually hit. L3: `T.eq(typeof T.mod('./logger.js').default, 'function')` AND `T.expect(T.mod('./logger.js').log === undefined, 'a default export is not also a named one')`. L4: the SAME two files are run twice by the harness — once concatenated as classic scripts (which is exactly what runner.js does today) and once as modules; test asserts the collision happens in mode 1 (`T.eq(classicResult, 3)` — one `let items` clobbered the other) and does not in mode 2 (`T.eq(T.mod('./cart.js').count(), 2)` and `T.eq(T.mod('./wishlist.js').count(), 3)`). L5: `db.js` logs `db connected` at load and is imported from two places; test asserts `T.eq(T.logs().filter(l => l === 'db connected').length, 1)` — exactly one, not two. Then a deliberate cycle: assert the imported binding is `undefined` at cycle time, and that moving the call inside a function makes the same test pass.

### 4. Unit 4 — Versions, ranges and the lockfile
Semver as arithmetic you can implement: MAJOR.MINOR.PATCH, numeric comparison, what ^ and ~ really match (including the 0.x special case), picking the highest satisfying version, building a lockfile, and npm install vs npm ci.

Lessons:
  - Semantic versioning
  - What ^ and ~ actually mean
  - Resolving a tree
  - The lockfile is the receipt
  - npm install vs npm ci
  - Unit 4 quiz: Versions

Graded how:
Every lesson is a PURE FUNCTION on plain objects — kind js, WORKS TODAY, zero engine. This is the find that makes the course cheap: the hardest concept in npm is the easiest one to auto-grade. L1: learner writes `bumpFor(kind)` and `compare(a,b)`. Test: `T.eq(compare('1.10.0','1.9.9'), 1, 'compare NUMBERS — as strings, "1.10.0" < "1.9.9"')` (the trap), `T.eq(compare('2.0.0','2.0.0'), 0)`, `T.eq(bumpFor('removed a function'), 'major')`. L2: learner writes `satisfies(range, version)` handling `^`, `~`, exact and `*`. Test runs ~14 pairs including `T.expect(satisfies('^1.4.2','1.9.0'))`, `T.expect(!satisfies('^1.4.2','2.0.0'))`, `T.expect(!satisfies('~1.2.3','1.3.0'))`, and the one almost nobody knows: `T.expect(!satisfies('^0.2.3','0.3.0'), 'below 1.0.0, ^ only allows PATCH — 0.x minors are breaking')`. L3: learner writes `pickVersion(range, available)`. Test: `T.eq(pickVersion('^1.4.0', ['1.4.0','1.9.4','2.0.0']), '1.9.4', 'highest that SATISFIES, not highest that exists')` and `T.eq(pickVersion('^3.0.0', ['1.4.0']), null)`. L4: learner writes `buildLock(manifest, registry)` walking transitive deps. Test asserts the exact lock object for a 3-package graph with `T.eq`, then asserts determinism: build it twice from objects whose keys were inserted in different orders and `T.eq(JSON.stringify(a), JSON.stringify(b), 'a lockfile that changes order on every run is useless in a diff')`. L5: learner writes `ciCheck(manifest, lock)` returning `{ok, reason}`. Test asserts `T.eq(ciCheck(drifted, lock).ok, false)` with a reason naming the drifted package, and `T.eq(ciCheck(matching, lock).ok, true)`.

- `node file.js` has to execute learner code, which means the shell branch cannot stay on the main thread; it needs a VFS→worker→results round trip. This is the only architecturally awkward piece and it is easy to underestimate, especially with the existing 7s watchdog and the requirement that tools/validate.js exercise it in real Chromium (solutions must pass, starters must fail).
- Currency risk on the trust unit. npm v12 (July 2026) blocks install scripts by default, which partly obsoletes the lesson's punchline within months of writing it. MITIGATION: write the lesson as history-plus-consequence — here is what install scripts did, here is why npm changed the default, here is why every project and CI runner you inherit is still on the old behaviour — rather than as a current-events warning that dates.
- Scope creep toward a fake Node. The moment there is a `node` command, it is tempting to add fs, http, EventEmitter and streams — at which point this becomes a worse Course 7 and a much bigger engine. HARD BOUNDARY: `node` runs scripts that print to stdout and exit. No server, no fs module, no event loop lessons. If a Node-runtime course is ever wanted, it is a separate proposal.
- Two items in the plan are honestly weak as auto-graded lessons and I would rather say so than pad: `npm audit` output is a fixture the learner reads rather than code they write, and 'choosing a package' is judgment. Both are handled as a pure-function proxy (riskScore over fixtures) plus quiz questions. If that still feels thin at authoring time, cut them to a cheatsheet entry and drop the course to 32 items rather than shipping a checkpoint that asserts nothing real.
